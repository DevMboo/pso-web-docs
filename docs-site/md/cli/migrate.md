# pso migrate

> Bring files generated by an earlier PSO version up to date without touching your own code: shows what would change (the fixed 10 s shutdown timer of older orchestrators becomes shutdownOnSignals); --apply writes it and keeps the previous file as <file>.bak

Bring files generated by an earlier PSO version up to date without touching your own code: shows what would change (the fixed 10 s shutdown timer of older orchestrators becomes shutdownOnSignals); --apply writes it and keeps the previous file as <file>.bak.

## Usage

```text
pso migrate [--apply] [--service name] [--json]
```

## Flags

`--apply`, `--service`, `--json`.

## Examples

```bash
pso migrate
pso migrate --apply
```

## Failure cases

- Exit 1 after a preview means a change is pending: run it again with `--apply`.
- `MANUAL`: the signal handling in src/main.ts was edited, so it is not rewritten; replace your handlers with `shutdownOnSignals(app)`.

## Exit codes

`0` on success, `1` when the command ran and failed. See the [exit code table](cli/index.md#exit-codes).
